# Team Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each milestone (M1–M8) is a shippable increment.

**Goal:** Add multi-user team collaboration to Vento on top of self-hosted Appwrite, with Postman-style conflict resolution, OAuth deep-link sign-in, OS-keychain secrets per device, and a fully functional anonymous local mode.

**Architecture:** Sync engine in pure TypeScript (`src/sync/`), Tauri capabilities behind port interfaces (`src/ports/`) with Tauri-specific adapters in `src/adapters/tauri/`. Appwrite Functions enforce version CAS for every write. Local SQLite serves as cache. Realtime over Appwrite WebSocket channels. Multipart files in Appwrite Storage.

**Tech stack additions:** Appwrite JS SDK (`appwrite`), `tauri-plugin-deep-link` v2, UUIDv7 generator, optional `dependency-cruiser` for import-boundary lint.

**Test posture:** Existing project has no JS/TS test framework. Continue with `npm run build`, `cargo check`, and explicit manual smoke steps per task. Sync engine ships with a minimal unit-test runner (TBD: Vitest) introduced in M1 because state-machine correctness matters too much for manual-only.

**Spec:** `docs/superpowers/specs/2026-05-20-team-sync-design.md`
